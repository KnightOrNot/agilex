# ADR 0003：新版 HABITS 与分支验收门槛

- 日期：2026-11-08。
- 状态：已接受，依据用户替换的 HABITS 和本轮直接 main 发布指令。
- 背景：2026-11-05 曾删除长期 dev；新版习惯要求恢复 dev 集成、每次从 dev 建独立工作分支，并在任何 commit 前获得用户实物测试通过确认。
- 决定：采用新版习惯，活动规则集中在 [git.md](../../git.md)。此项取代 ADR 0001 的后续长期分支策略，不改写历史已发生事实。main 作为稳定分支，之后按保护规则与获授权的发布流程合并。
- 一次性例外：本轮纯规范/检查入口/元数据调整由用户明确授权最后一次直接 commit/push main。未执行或声称通过物理测试；这项指令覆盖本轮原本的等待确认门槛，不延伸到后续任何 commit。
- 实施：0.2.0→0.2.1 只递增一次；用户新 HABITS 原样保留。增加 SKILLS 路由、PR 验收模板，CI 覆盖开发分支；main 同步后由同一提交建立 dev，不改五个子模块分支或 gitlink。
- 范围：当前阶段仍为 TESTING；发布/热修复具体合并与清理细节待确认，不自动打标签、部署或修改 GitHub 保护设置。
- 技能适配：/ship 的功能分支/PR 前置与本轮用户明确 main 例外不同，本轮按项目授权直接交付；未宣称执行其完整流水线。收尾使用 caveman:verify-and-stop，复用匹配内容的检查证据。
- 证据与遗留：[testing](../stages/testing.md)。
