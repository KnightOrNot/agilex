# ADR 0005：到位容差统一为 1.5°

- 状态：已接受；来源为用户 2026-11-17 的明确指令。
- 背景：P0 已完成，冻结版本的 CLI 使用 1.0°、Web 使用 1.1°；Web B3 退出回零残差为 1.024°。用户说明机械臂实际误差较大，要求统一采用 1.5° 基线，决定不再继续容差实验。
- 决定：CLI `move_js`/`movejs`、Web 及新 runtime 的默认到位判据统一为每轴绝对角度误差 ≤1.5°。保留显式覆盖能力；运行时使用 `motion.position_tolerance_deg`，旧 Web 使用 `collection.position_tolerance_deg`，旧 CLI `movejs` 使用 `--tolerance-deg`，其默认值同步。后续入口迁移再收口到统一 motion 配置。
- 生效范围：启动回零、主手对齐、退出回零的到位判据；取代 [ADR 0001](0001-baseline-and-validation.md) 中仍在使用的容差分叉，以及 [ADR 0004](0004-hal-service-architecture.md) 原统一 1.0° 目标，更新 [架构基线](../specs/architecture-v3.3.md) D11、§7.5、验收项 13 与 P3 判据。
- 验证：采用软件回归核对容差内接受、超差拒绝和参数默认值。按用户决定不追加专门容差真机实验，也不把参数变更描述成新的硬件精度测量。后续服务化功能验收继续按对应阶段执行，使用 1.5° 判据。
- 证据保全：P0 报告、黄金数据、源快照、1.0°/1.1° 原判据、残差和哈希均保持原样，不追溯改写既有测试结果或要求重采。
- 后果与边界：接受误差范围扩大，但不会修改实际反馈、零偏、标定、关节限位、目标步长、反馈有效性/新鲜度、运动授权或断令验证状态；超过配置容差仍报错。
