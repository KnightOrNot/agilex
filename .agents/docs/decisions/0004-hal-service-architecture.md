# ADR 0004：HAL 服务化架构与分阶段迁移

状态：设计接受；P1 软件验证通过，准备 dev 异机待测快照，真机验收未完成。日期：2026-11-11。

用户在多轮评审 [v3.3 架构基线](../specs/architecture-v3.3.md) 后授权开始实施。目标为适配不同主手、从臂、相机和新增传感器；契约、runtime、驱动与导出器各自承担明确职责。

本决定允许按架构路线逐步重排运行时代码，取代 conventions.md 中「不因规范化重排运行时代码」对本次有目的迁移的限制；旧入口在验收前保留。两种记录模式、独立子模块与可配置的 1.0° 容差是目标设计，P1 不修改现有真机路径或现有容差。

新契约包先在独立本地仓库开发；用户随后明确授权先提交 dev 供异机真机实验，并创建 agilex-contract 远端。本地项目名、目录、Python 导入统一为 agilex-contract / agilex_contract，子仓 dev 先推送，父仓再固定其 gitlink。该分发例外见 git.md，不能解释为真机已通过或稳定版发布。原有五个 gitlink 不变，adapters/GELLO 的移除与重命名按 P7 执行。

故障默认报错停止；已有回零反馈/CAN/状态保护继续有效。断令后的硬件行为仍为 unverified。P1/P2 仿真可先行；依赖硬件的 P0/P3+ 验收保留原授权与证据门槛。

执行范围与验收见 [P1 计划](../specs/architecture-p1-plan.md)。设计冻结不等于实现、发布或硬件验收完成。

## 2026-11-17 后续决定

到位容差现按 [ADR 0005](0005-position-tolerance-baseline.md) 统一为 1.5°，用户决定不再补做容差实验。本文件原 1.0°/1.1° 说明保留为历史背景，P0 原始判据与测量不变。


## 2026-11-18 P2 执行边界

P0 已由用户验收完成；P2 继续只连接 synthetic HAL。统一 runtime 的配置、边界计数、raw v3、检查/回放、独立故障期限与私有命令服务见 [P2 计划](../specs/architecture-p2-plan.md)。软件完成状态和评审证据以 [测试记录](../stages/testing.md) 为准，P3～P7 不因 P2 软件验证自动完成。

P0 当前测量 profile 的队列未出现满队列，观察峰值较低；因此 P2 保留隔离写盘线程和 ZMQ multipart 传帧，不提前增加共享内存或写盘进程。该结论只支持现有负载下的实现选择，不是新 runtime 的多相机 90 FPS 吞吐验收；P4 必须按真实 raw 写入负载复测。边界 1 秒/排空 5 秒仍是仿真默认，不能直接覆盖 P0 中约 13～16 秒的 Web LeRobot 保存阶段，后续导出另设完成期限。
